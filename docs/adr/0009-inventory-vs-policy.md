# ADR-0009. 재고와 정책을 분리한다 — 원본이 둘이 되는 문제

## 상태

확정 (재검토 조건 명시)

## 맥락

*채널·PMS·대사가 무엇인지부터 필요하면 `docs/07-reconciliation.md` 의 0장을 먼저 읽는다.*

이 저장소의 모든 설계는 한 문장 위에 서 있다.

```
우리 PMS = 원본(source of truth)
채널     = 사본. 우리가 밀어넣은 값
```

`00-problem-definition.md`가 다루겠다고 선언한 것은 두 지점이다 —
**(a) dual-write**, **(b) 중복 수신**. 둘 다 "우리 → 채널" 방향의 문제다.

그런데 채널매니저 Channex 는 `ari` 웹훅을 제공한다.
재고·요금·제약이 **채널매니저 UI 나 채널 앱에서 사람 손으로 바뀌었을 때** 우리에게 통보하는 웹훅이다.

이 웹훅이 존재한다는 것은 **사본 쪽에서도 값이 바뀐다**는 뜻이다.
그리고 현장에서 실제로 바뀐다.

- 사장님이 채널 앱에서 직접 마감을 풀거나 건다
- 채널매니저 화면에서 노출 수를 손으로 조정한다
- 전화·워크인 예약을 채널 쪽에만 반영한다

이것은 **(c) 역방향 쓰기**이며, 선언되지도 제외되지도 않았다(#21).

### 순진한 답 두 개가 모두 틀리다

| 답 | 왜 틀리는가 |
|---|---|
| **우리가 항상 이긴다** | 사장님의 조작을 매번 되돌린다. 사람은 다시 바꾼다. 무한 루프가 되고, 현장은 시스템을 신뢰하지 않게 된다 |
| **최신 타임스탬프가 이긴다** | 재고의 원본이 둘이 된다. 이 저장소의 유일한 주장이 무너진다. 게다가 웹훅은 순서 보장이 없어 "최신"을 알 수도 없다 |

두 답이 다 틀린 이유는 같다. **하나의 값으로 취급했기 때문이다.**

## 결정

**하나로 보였던 것을 세 축으로 나눈다. 축마다 원본은 하나다.**

| 축 | 무엇인가 | 원본 | 어긋났을 때 |
|---|---|---|---|
| **예약 사실** | 누가 언제 무엇을 샀는가 | **채널** | 채널이 이긴다. 흡수만 한다 |
| **재고 수량** | 남은 방이 몇 개인가 | **우리** | 우리가 이긴다. 계산값을 재발행한다 |
| **채널 정책** | 이 채널에 몇 개를 어떻게 보일 것인가 | **양쪽** | 판정한다 (아래) |

여기서 이 ADR 의 전부인 한 문장이 나온다.

> **`ari` 웹훅은 "재고가 틀렸다"가 아니라
> "정책이 우리 모르게 바뀌었다"로 읽는다.**

### 왜 이 독법이 성립하는가

채널 화면에서 사람이 바꿀 수 있는 것은 **실제로 정책이다.**

사장님이 채널 앱에서 "2실만 팔아라"로 바꾼 것은 물리적 객실 수를 2로 바꾼 것이 아니다.
**그 채널의 노출 상한을 2로 걸은 것**이다. 방은 여전히 10개다.

물리적 재고를 바꾸는 사건은 세 가지뿐이고, 전부 우리를 지나거나 예약 축으로 들어온다.

```
예약 확정 · 취소       → 예약 축. 채널이 원본. 우리가 흡수한다
객실 상태 변경(고장)   → 우리 축. 우리가 원본
정책 변경(마감·상한)   → 정책 축. 재고가 아니다
```

**재고를 바꿀 수 있는 경로에 채널 화면이 없다.** 그래서 원본이 둘로 갈라지지 않는다.

### 정책 축의 판정 규칙

```
ari 웹훅 수신
   │
   ├─ payload.user_id == 우리 앱 ?  ──▶ 버린다 (에코)
   │
   └─ 사람이 바꿨다
        │
        ├─ 우리 정책 장부와 일치 ?  ──▶ 아무것도 하지 않는다
        │
        └─ 불일치
             ├─ 화이트리스트에 있는 정책  ──▶ [흡수] 장부에 반영한다
             └─ 그 외                     ──▶ [교정] 장부 값으로 되돌리고 알린다
```

**기본값은 교정, 흡수는 화이트리스트다.** 근거는 예약 축과의 대칭이다 —
예약은 되돌릴 수 없으니 무조건 흡수하고, 정책은 되돌릴 수 있으니 기본은 교정한다.
조용히 흡수하면 장부가 언제 왜 바뀌었는지 아무도 모르게 된다.

`user_id` 필터는 우리가 만든 장치가 아니라 Channex 가 payload 에 넣어 주는 값이다.
공개 문서가 용도를 명시한다 — *"자기 앱이 만든 변경을 무시하고 싶을 때 쓸 수 있다"*.

## 이 결정이 만드는 것

**1. 채널 정책 장부.** 정책의 원본을 우리 DB 에 둔다. 재고 테이블은 건드리지 않는다.

**2. 장부 → 채널 투영.** Channex 는 채널별 availability 를 받지 않는다.
availability 는 룸타입 단위 절대값이고, 채널별 차등은 규칙 세 가지로만 표현된다.

| 규칙 | 의미 |
|---|---|
| `close_out` | 이 채널에는 팔지 않는다 |
| `availability_offset` | 전체에서 N 을 빼고 보여준다 |
| `max_availability` | 최대 N 까지만 보여준다 |

즉 정책 장부는 **카운터가 아니라 투영 규칙의 원본**이다.

**3. 에코 필터.** 우리가 밀어넣은 변경이 되돌아오는 것을 `user_id` 로 걸러낸다.

## 불변식은 늘어나지 않는다

이 결정에서 가장 중요한 귀결이다.

**정책은 불변식이 아니라 수렴 대상이다.**

```
재고 : 언제 어느 순간에도 참이어야 한다        → INV-1 · INV-2 · INV-3
정책 : 유한 시간 안에 장부 값으로 수렴하면 된다  → 불변식 아님
```

채널의 정책 값이 지금 우리 장부와 다른 것은 **위반이 아니다.**
다음 대사 주기에 수렴하면 정상이다. B6 이 재고에 대해 하는 일과 같은 성질이다.

따라서 이 ADR 은 **`INV-` 를 하나도 추가하지 않는다.**
검증해야 할 등식이 늘지 않고, T1~T4 는 그대로 유효하다.

## 기각한 대안

### 대안 1: 우리가 항상 이긴다 — 교정 전용

정책 축을 없애고 모든 `ari` 웹훅을 "덮어쓸 대상"으로 취급한다.

기각 이유는 **루프**다. 사람이 화면에서 바꾸는 데는 이유가 있고, 되돌리면 다시 바꾼다.
그리고 이 구조는 현장에 "시스템이 내 조작을 먹는다"를 학습시킨다.
`00-problem-definition.md`가 문제 삼은 **확인 업무**를 오히려 늘린다.

### 대안 2: LWW (Last Write Wins) — 최신 타임스탬프가 이긴다

기각 이유가 둘이다.

- **원본이 둘이 된다.** 재고 수량의 최종 권위가 상황에 따라 달라진다
- **"최신"을 알 수 없다.** Channex 공개 문서가 명시한다 — *"웹훅 호출의 순서는 이벤트 발생 순서와 다를 수 있다"*.
  타임스탬프 기반 판정은 순서 보장이 없는 채널에서 성립하지 않는다

### 대안 3: 채널별 재고 카운터를 둔다

정책이 아니라 재고를 채널별로 쪼갠다. ADR-0001 의 allocated / hybrid 가 이것이다.

기각 이유는 **표현 수단이 없다**는 것이다.
Channex 의 availability push 는 룸타입 단위이며 채널별 값을 받지 않는다.
채널별 카운터를 우리 DB 에 만들어도 채널에 그대로 내보낼 방법이 없고,
결국 규칙으로 투영해야 한다 — 즉 이 ADR 의 정책 축으로 되돌아온다.

ADR-0001 개정본의 캡형·보장형 구분이 여기서 나온다.

## 결과

**`00-problem-definition.md`의 (c) 역방향 쓰기가 범위에 들어온다.**
다만 전면 양방향 동기화가 아니라 **정책 축으로 좁혀서** 들어온다.
재고 축의 원본은 여전히, 그리고 앞으로도 우리다.

대사의 구체적 설계 — 세 방향, ack 순서, 취소·수정 처리 — 는 `docs/07-reconciliation.md`.

**남는 부담은 장부 하나와 투영 로직이다.** 카운터도, 불변식도 늘지 않는다.

## 재검토 조건

1. **채널 화면에서 물리적 객실 수를 바꿀 수 있게 된다** — 이 ADR 의 전제("재고를 바꿀 수 있는 경로에 채널 화면이 없다")가 깨진다
2. **정책 흡수 화이트리스트가 사실상 전체가 된다** — 그때는 정책의 원본이 채널이라는 뜻이므로 축의 방향을 뒤집어야 한다
3. **교정 알림이 운영 소음이 된다** — 판정 규칙의 기본값을 교정에서 흡수로 바꿀 근거가 된다

## 결론

원본이 둘이 되는 문제를 **어느 쪽이 이기는가**로 풀지 않았다.
**무엇에 대해 이기는가를 나누어** 풀었다.

한 값을 두고 다투면 답이 없다. 축을 나누면 축마다 답이 하나다.
