# ADR-0001. Pooled Inventory 모델을 채택한다

## 상태
확정

## 맥락

다채널 판매에서 재고를 관리하는 방식은 두 가지다.

**Allocated (배정형)** — 채널별로 고정 수량을 나눠준다.
에어비앤비 3, 야놀자 3, 직판 4.

**Pooled (공유형)** — 모든 채널이 하나의 재고 카운트를 바라본다.
어느 채널에서든 팔리면 즉시 전 채널에 반영한다.

## 결정

**Pooled를 채택한다.** 스키마상 `daily_inventory(room_type_id, stay_date, total, sold)`
단일 행이 모든 채널의 재고를 대표한다.

## 기각한 대안: Allocated

기각 이유는 **인위적 품절**이다.
에어비앤비 배정분 3이 모두 팔렸는데 야놀자에 2가 남아 있으면,
에어비앤비 고객은 "품절"을 보지만 실제 객실은 비어 있다.
숙박업의 재고는 소멸성 자산이므로 이 손실은 회수되지 않는다.

Allocated의 장점은 동시성 경합이 채널별로 분산된다는 것이다.
그러나 이는 매출 손실을 대가로 얻는 기술적 편의이며, 우선순위가 역전되어 있다.

## 결과

**경합이 단일 행에 집중된다.**

인기 지점의 주말 날짜는 모든 채널의 예약 요청이 동일한
`(room_type_id, stay_date)` 행으로 수렴한다.

따라서 이 시스템에서 **락 전략은 부수적 구현 세부사항이 아니라 핵심 설계 결정**이 된다.
→ ADR-0002로 이어진다.

부수적으로, 채널 재고 동기화의 필요성도 여기서 나온다.
Pooled는 "어느 채널에서 팔려도 다른 모든 채널에 즉시 반영"을 전제하므로,
반영 실패는 곧바로 오버부킹이다.
